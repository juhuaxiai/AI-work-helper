# 智能 OnCall 工作台改造 PRD

**状态**　讨论稿，待评审。本文描述一次完整升级。需求确认后再转为 OpenSpec 正式变更。

## 1. 背景与目标

ChatAgent 是被诊断的实时语音业务，链路涉及 RTC、ASR、LLM、MCP Router、TTS 和客户端播放。Agent Py 是运行排障、验证和知识问答的 OnCall 工作台。当前优先验证「语音回复变慢」这一个业务场景，覆盖从故障信号进入工作台到生成可追溯报告的全过程。

| 现状 | 升级目标 |
| --- | --- |
| 当前用本地用户 ID 划分数据范围，默认只检索个人知识库 | 按企业隔离数据，按部门开放排障能力。本部门可诊断和审批，其他部门使用普通对话。个人资源保留原归属 |
| LangGraph 已有诊断编排、后台任务、流式事件、证据和报告。当前规划最多保留一次 CLS `SearchLog`，后续分支按既有步骤是否完成决定 | 诊断 Agent 根据查到的证据选择下一步。存在可验证的假设时，把验证委派给独立的验证 Agent |
| 已支持从 Alertmanager 或 Prometheus 读取活跃告警，用户可以点告警启动诊断 | 工作台收到告警后主动提醒，按规则决定是否自动排队诊断，结果回到原告警 |
| 已保存阶段快照和任务事件，现有图未接入可暂停后继续执行的 Checkpointer | 高风险测试经授权人员审批。服务重启后可继续，重复审批和任务重试保持同一执行身份 |

保留现有对话、RAG、知识文档管理、MCP 连接、诊断历史、证据链、案例和反馈能力。组织身份使用本地演示数据，参照飞书字段。业务诊断读取真实数据源。执行范围是预设分析和独立测试环境里的验证，生产系统只提供经授权的只读观测能力。

## 2. 使用者与组织权限

| 使用者 | 可以做什么 | 默认数据范围 |
| --- | --- | --- |
| 本部门成员 | 使用普通对话 Agent、查看告警、调用故障分析工具、申请和审批测试验证、查看授权范围内的诊断报告 | 本企业共享知识、个人私有资源，以及授权服务和环境的运维 SOP、日志、Trace、指标与诊断证据 |
| 其他部门成员 | 使用普通对话 Agent、检索可见知识、查看自己的对话历史 | 本企业共享知识和个人私有资源 |

### 组织身份与授权规则

- 本地组织资料沿用 `tenant_key`、`open_id`、`department_ids`。它们分别表示企业、应用内成员标识和所属部门。已有登录态用于验证身份，后端根据可信的本地账号绑定读取企业及成员归属。 [飞书用户身份](https://open.feishu.cn/document/platform-overveiw/basic-concepts/user-identity-introduction/introduction) · [飞书用户信息](https://open.feishu.cn/document/server-docs/contact-v3/user/get)
- 企业是跨组织隔离边界。每个企业在本地配置中指定一个具备诊断和审批权限的部门，对应本企业的「本部门」。只要成员的 `department_ids` 包含该 ID，就归入本部门。其他已绑定的企业成员归入其他部门。新增注册用户默认没有企业敏感权限。演示以本企业两类成员为主，另用一家企业的本部门账号验证跨租户隔离。
- 迁移保留个人对话、知识库和报告的原有归属。普通对话检索本企业共享知识和个人私有知识，运维 SOP 为受限数据。通知、历史和报告的访问同时检查用户类别、企业和资源归属。
- 后端在路由、API 访问、Worker 执行和工具调用时核验企业、部门归属和资源范围。普通对话 Agent 只加载对话和知识问答所需工具。故障分析工具经本部门权限检查后，在授权的企业、服务和环境内运行。知识检索在向量和关键词召回前限定企业及可访问的知识库，引用、原文下载与索引任务详情也使用同一范围。报告和审计链接打开时重新鉴权。
- 账号切换、部门变更和授权撤销都需要刷新有效权限。待执行任务在权限撤销后不能继续敏感步骤。账号身份无法解析时拒绝组织资源访问。自动告警使用受限的租户服务身份，其权限由告警源授权配置限定。

## 3. 产品需求清单

| 编号 | 功能 | 行为与交付范围 |
| --- | --- | --- |
| R01 | 本地组织身份 | 通过现有本地登录识别企业成员。资料和测试样例参照飞书字段。本次交付在本地完成身份与授权演示，保留以后增加真实身份适配器的接口边界 |
| R02 | Agent 路由 | 工作台向两类成员提供同一个普通对话入口。仅本部门成员可以进入智能诊断和审批。聊天中的故障问题可以提示本部门成员进入诊断，成员确认后才创建诊断任务。后端对诊断入口、任务和工具执行同样的授权检查 |
| R03 | 知识库访问 | 普通对话可以检索和引用本企业共享知识与个人私有知识。本部门成员可在诊断流程中检索获授权的运维 SOP。上传、索引、查询和引用均按相同的资源可见范围执行 |
| R04 | 故障入口和实时提醒 | 支持手动填写现象、从活跃告警发起、通过 Alertmanager 推送事件。测试环境配置一条基于 TTS 指标的监控规则。配置允许的企业和来源后，事件进后台并按告警指纹和发生周期去重。在线用户收到工作台通知，离线期间的告警可查历史。自动诊断按明确规则开启，已解除的告警更新原记录 |
| R05 | Diagnosis Agent | 先确定服务和时间范围，检索 SOP，再根据证据选择日志、Trace、指标或知识查询。保留步骤、工具、证据引用、根因假设、未解决问题和验证建议。达到查询预算、遇到超时或无数据时，给出已有证据和缺口 |
| R06 | 可替换的观测数据源 | 把当前 CLS 专用查询改成可替换的工具接口，支持内网日志、Trace 和 Metrics 来源。保留 CLS 适配供已有部署继续使用。诊断流程按服务、环境、时间段和可用关联 ID 查询，只接受真实来源的结果 |
| R07 | 日志导出 | 常规查询返回有界的脱敏摘要。需要统计大量数据时，经授权导出，返回限范围、大小和有效期的文件引用。归属、有效期和访问限制随引用保留，导出和读取有审计记录 |
| R08 | 条件委派 | 当证据有缺口、假设可验证且存在授权的测试模板和目标时，由 LangGraph 委派。证据充分时直接出报告，证据不足且无合适验证方式时生成有限结论。每次委派或跳过都保存理由 |
| R09 | Verification Agent | 接收结构化假设与获准证据，独立选择预设实验，确定对照条件和结果判断。TTS 验收至少提供消费并发对照和合成耗时基线两种模板。向执行器提交结构化计划，分析实际输出，明确结果支持假设、未复现、证据不足、执行失败或被拒绝 |
| R10 | 沙箱日志分析 | 对脱敏日志运行预设清洗与统计模板，输入只读，默认无网络，结果回到当前诊断任务 |
| R11 | 沙箱测试验证 | 在容器里运行受控测试客户端，只允许访问独立测试环境。执行器校验目标和参数上限，注入短期测试权限，保留运行摘要、退出状态与证据引用 |
| R12 | 审批 | 审批卡片在本地工作台展示测试目标、模板、范围、资源上限和待验证假设。本部门成员可批准或拒绝本企业授权范围内的计划。拒绝、过期或计划变更可回到报告流程，产生需补充的结论或重新发起审批 |
| R13 | 恢复和取消 | 保存流程状态、审批记录、任务进度和外部执行编号。等待审批期间释放 Worker。重启后恢复原任务，重复事件或重复点击只改变一次有效状态。用户可取消任务，执行器能回收进行中的运行资源 |
| R14 | 报告、案例与审计 | 报告区分观测事实、根因假设、实验结论、限制和处理建议，每个重要结论带证据来源。沿用历史、反馈与案例沉淀，按访问级别决定谁可查看和检索。测试环境报告保留环境标记，沉淀时继续带有对应范围 |
| R15 | 工作台交互 | 显示当前企业和部门。根据部门权限展示活跃告警、阶段进度、审批状态和最终报告。实时事件按同一权限范围更新工作台，刷新或断线后从持久化数据恢复。保持现有桌面与窄屏交互 |
| R16 | 凭据与证据保护 | 前端只读取明确允许公开的配置。日志服务、模型、执行器使用服务端凭据。模型和报告只得到经授权且脱敏的内容。使用外部 Qwen 时发送已允许的摘要和引用，原始日志和其他敏感资料保留在受控存储 |
| R17 | 对话与上下文隔离 | 企业内的会话、消息、记忆摘要和会话级设置按企业及所有者隔离，保留已有个人会话的归属。每轮根据登录态与当前权限装配知识范围和工具。上一轮的工具结果、引用及摘要进入模型前遵守当前权限。更换账号或企业时清除上一身份的页面状态和进行中的对话流 |

### 普通对话如何使用组织身份

- 两类成员共用现有聊天 Agent、会话界面和流式回复。后端根据当前登录账号解析企业和成员身份，限定会话列表、详情、续聊、删除和记忆读取。公司知识共享给本企业成员，个人聊天记录和记忆仍归个人。
- 普通对话可以查询本企业共享知识和个人知识库。日志、Trace、指标、运维 SOP 和验证执行留在获授权的诊断流程中。现有聊天会加载连接上发现的 MCP 工具，并可能回退到默认 CLS 连接。接入组织隔离后，聊天流程按允许的工具清单装配，所有真实调用也按当前身份鉴权。
- 用户在聊天里输入「帮我查 TTS 卡顿」时，普通对话可以根据可见知识解释排查思路。本部门成员可以在确认后进入智能诊断，把选定的故障描述带入新任务。其他部门留在普通对话。诊断任务的上下文和证据由诊断流程独立读取和授权。

### 正式部署的会话存储

- 正式部署优先用 MongoDB 作为聊天存储，保存会话、最终消息、会话记忆摘要和引用。会话与消息各自独立存储，历史按会话分页读取，每次生成使用摘要与所需的近期消息。账号、企业成员关系、权限、审批和后台任务由关系数据库负责。
- 聊天存储由现有仓库接口提供。MongoDB 的会话和消息带有企业、所有者标识，每次查询、续聊和删除都按后端认证上下文限定范围。涉及审批或诊断的引用由相应资源服务重新鉴权。聊天存储与业务库通过稳定 ID 关联，聊天数据以当前选定的会话存储为准。
- 本地开发继续支持当前 SQLite 实现。启用 MongoDB 时，已有会话可以按稳定 ID 迁移，保留历史顺序、摘要、引用和原有归属。正式变更需补充 MongoDB 的隔离和分页测试，并检查删除与迁移恢复。

## 4. 多 Agent 设计与端到端流程

保留两个实际承担不同推理职责的 Agent。**Diagnosis Agent** 对服务观测数据有只读访问权限，负责根据证据提出可证伪的假设。**Verification Agent** 接收假设和证据引用，负责从批准的实验模板中选择方法、确定对照、解读输出。两者可以共用现有 Qwen 接入和同一个后端进程，各自拥有独立工具和结构化输入输出。日志、Trace、指标、RAG 和沙箱执行器是工具。

附件中的 Supervisor 职责保留在 LangGraph 工作流。入口、身份、服务范围、预算、委派、审批和终止由规则决定，模型参与需要语义判断的规划和报告。这个职责分配能独立验证两种 Agent 的决策，也能对敏感步骤进行可重复的权限测试。

```text
本地登录 ── 后端授权 ── 知识问答 ── 聊天 Agent + 可见知识库
                       │
                       └─ 智能诊断 ── Diagnosis Agent ── 证据与假设
告警推送 ── 来源授权与去重 ───────────┘                    │
                                                          ├─ 证据充分或无合适实验 ── 报告
                                                          └─ 条件满足 ── Verification Agent
                                                                         └─ 审批与策略校验
                                                                            └─ 沙箱测试 ── 报告
```

### ChatAgent 语音回复慢的排障场景

1. 运维从告警或手动报障进入任务，确认要查的服务、环境、时间窗口。测试环境可采用现有可控的 ChatAgent 部署，或专门的 TTS 试验服务。测试服务需在实际运行时产生有标识的日志、Trace 和指标。
2. Diagnosis 先查关键链路的 Trace。当耗时集中在排队阶段时，下一步查队列长度、等待时长和消费速率，再关联请求日志和 SOP。当耗时集中在合成或客户端播放时，转向该阶段的证据。相关数据采用统一请求或 Trace 标识与时间口径。
3. 把「消费侧积压」写成可检验的假设。证据充分可以出报告。仍缺对照时，把假设、已知证据、未确认因素交给 Verification。若测试目标、模板或权限不可用，报告说明无法验证的原因。
4. Verification 在独立环境选择对照模板，例如控制文本、模型和输入负载，只调整测试服务的消费并发，比较队列等待、合成耗时和 TTS 首包延迟。没有客户端播放埋点时，只对已观测环节下结论。测试环境结果用来支持或削弱该假设，生产根因仍需对应环境的证据。
5. 最终报告列出实际观察、关键证据 ID、假设、实验条件与结果、适用范围、处理建议、未确认事项。按钮和链接展示任务进度、报告与证据，权限随资源校验。后续可用同一工作流接入 MCP Router 超时、播放异常、打断后旧任务未取消等场景。

### 工具与数据边界

| 工具 | 输入与权限 | 输出 |
| --- | --- | --- |
| `query_traces`、`search_logs`、`query_metrics` | 授权服务与环境、受限时间窗、可选 Trace ID 或允许的查询条件 | 有界数据、来源、时间、查询状态、证据引用 |
| `search_knowledge` | 从已授权知识库范围内查找 SOP、文档和历史案例 | 可追溯来源与引用。无命中时明确返回空结果 |
| `export_logs` | 受限导出范围、数据上限和脱敏规则 | 有效期和权限绑定的文件引用及摘要 |
| 日志分析工具 | 已脱敏文件引用、预设分析模板和有界参数 | 统计输出、运行状态、证据引用 |
| 验证执行工具 | 审核通过的计划、预设模板、固定测试目标和执行编号 | 实验输出、执行状态、资源使用和证据引用 |

观测和知识接口与具体供应商分离。单元与合同测试可注入固定数据以覆盖超时、缺失、失败和未复现。可运行演示中，组织资料使用样例，日志、Trace、指标及容器结果由独立环境实际产生并标记环境。无法获得真实证据时，工作流保留缺口并返回有限结论。

## 5. 沙箱、审批与故障恢复

### 沙箱执行要求

| 项目 | 日志分析 | 测试验证 |
| --- | --- | --- |
| 执行对象 | 预设日志清洗或统计模板 | 预设测试客户端和模板，校验目标与参数 |
| 网络 | 无网络 | 只允许到指定测试服务，实际阻断生产、宿主机和未授权网络目标 |
| 输入 | 有效的脱敏文件引用，只读 | 经批准的计划、测试数据和短期测试凭据 |
| 容器 | 非特权、非 root、只读根文件系统、受限临时输出 | 同一运行约束，另加请求量、并发和持续时间限制 |
| 生命周期 | 限 CPU、内存、进程数、存储和执行时间，记录退出状态及有界输出，执行后销毁容器与临时材料 | 同左。取消或失败后可查询运行状态与回收结果 |

执行器独立持有容器控制权限，API、Agent 和业务容器不暴露 Docker socket 或宿主机凭据。生产写入、生产测试和任意脚本执行在受控执行范围之外，审批只能在已允许的策略范围内放行。沙箱执行镜像和模板版本纳入审计。涉及任意代码执行时，需要单独评审隔离强度和运行边界。

### 审批和恢复要求

- 等待审批是持久状态，记录任务、申请者、实际操作审批的本部门成员、允许范围、计划版本与失效时间。批准仅作用于界面上展示的那份计划。执行前再次校验当前权限和策略。拒绝、过期、取消或撤权可终止验证，保留已收集的诊断证据。
- 使用持久化 LangGraph Checkpointer 恢复计算流程，沿用现有 durable job runtime 做调度、租约、取消和事件保存。任务和图运行标识稳定，事件保留顺序与终态。从审批状态恢复后可在原任务查看进度。 [LangGraph 中断与恢复](https://docs.langchain.com/oss/python/langgraph/interrupts)
- 同一个验证计划只分配一个外部 `execution_id`。执行器按编号识别重复请求。遇到「执行可能已经开始但结果尚未持久化」的不确定状态，先按编号查询或标记待人工确认。告警接收使用持久去重，事件落库和任务的创建保持原子或可恢复，防止重复诊断和遗失告警。

## 6. 验收标准

| 场景 | 验收结果 | 覆盖需求 |
| --- | --- | --- |
| 同一企业的两类成员在聊天输入相同的查日志请求 | 两类成员均可检索共享及个人知识。本部门成员确认进入诊断后，可查看获授权的日志。其他部门直接调用诊断 API、诱导工具调用或提交审批时均被后端拒绝并审计 | R01–R03、R05、R12、R16、R17 |
| 两个企业都有同名的本部门 | B 企业本部门成员读取 A 企业的告警、任务、知识、报告和证据，或尝试审批其验证计划，都被拒绝。向量检索只返回获授权的数据 | R01、R03、R12、R14 |
| 成员转出本部门与已有个人数据迁移 | 成员转出后仍可普通对话，无法新建诊断、继续待执行的敏感步骤、审批或访问受限报告。原有个人会话和私人知识保持原归属 | R01–R03、R12–R14 |
| TTS 指标触发告警，Alertmanager 重发或发送恢复事件 | 同次事件只创建一个可见提醒。启用自动诊断的规则只创建一个任务，恢复事件更新原告警。禁用来源不阻塞有效的本地来源 | R04、R13、R15 |
| TTS 观测显示排队慢或合成慢 | 两种证据产生不同的后续查询。证据充分时直接出报告，日志或指标不可用时保留缺口，查询达到预算后结束 | R05、R06、R08、R14 |
| 诊断需要验证且测试环境可用 | Verification 选出有对照的模板并输出合法计划。审批后只在指定环境运行，记录实验结果和证据。未复现时报告保留不确定性 | R08、R09、R11、R12、R14 |
| 审批被拒绝、过期、撤权或修改了计划 | 未获有效审批的计划不创建执行。可以出具基于已有证据的诊断报告或提交新的计划 | R08、R12–R14 |
| 等待审批时重启，随后重复提交批准 | 状态可查，批准后从原任务继续。同一 `execution_id` 只执行一次，即使任务重试也能凭编号查到原执行结果 | R12、R13、R15 |
| 运行模板遇到超时、资源超限或越界网络请求 | 执行被限制并记录原因，容器及临时目录回收。独立测试目标仍可正常访问 | R10、R11、R13 |
| 导出日志、打开证据和检查前端资源 | 只有授权主体能获取脱敏材料，过期引用失效。浏览器可访问的资源和发给模型的摘要不含后台凭据或未经授权的数据 | R07、R14、R16 |
| 工作台刷新、断线和窄屏操作 | 恢复当前任务、状态、可见证据和可执行操作，进度与最终报告可通过现有流式客户端访问 | R13–R15 |
| 同一企业的另一个成员打开会话链接，或用户切换账号继续对话 | 其他成员无法读取或继续原会话。账号切换后无上一账号的消息、记忆或流式输出残留。撤销授权后，已失效的知识引用及相关上下文无法用于后续模型请求 | R01、R03、R17 |
| 将 SQLite 的已有聊天迁移到 MongoDB | 按原 ID 查询可恢复消息顺序、记忆摘要和引用。分页无重复或漏读，其他企业或成员无法读取或删除该会话。重试迁移不会重复写入 | R17 |

验证时保留一条可复跑的 TTS 故障链路。度量告警到工作台可见的耗时、诊断耗时、触发验证带来的额外耗时，以及验证后哪些假设得到支持或被降级。用同一组受控场景比较启用与跳过验证的报告结论。首轮记录观测值，再据此设定性能目标。

## 7. OpenSpec 拆分与实施依赖

### 本地测试基线

以下验证使用隔离数据，为后续变更提供验收基线。

| 环节 | 已验证的结果 |
| --- | --- |
| 文档到检索 | 通过 API 上传 TTS 测试 Markdown，后台任务切分并写入真实 Milvus，检索返回该文档引用。另一个账号检索不到该文档，直接读取返回 `403`。Embedding 和 rerank 使用本地测试替身 |

| 后台诊断到报告 | 在隔离测试实例中验证了任务入队、LangGraph、SSE、报告和证据关联。缺少 CLS 地域或主题时，诊断和后台任务均进入失败状态，历史保留原因，SSE 返回 `SYSTEM_UNAVAILABLE` |
| 本地 TTS 日志诊断 | 发出 HTTP 测试请求，服务记录实际等待时长和请求 ID。诊断通过本地 MCP 读取 JSONL，回退报告引用对应日志。空日志时报告提示证据不足。告警输入由测试提交 |
| 工具不可用 | 在诊断图可以启动、MCP 连接不可用时，验证了失败审计、证据不足报告、SSE 和阶段快照。其他账号访问报告返回 `403` |

相关后端测试通过 50 项，前端告警、诊断、聊天和契约测试通过 19 项。探测使用临时 SQLite、临时 Milvus 集合和独立 Alertmanager，测试资源已清理。真实日志根因诊断、部门级授权、主动告警推送、审批沙箱与第二个 Agent 仍是后续验收项。

### 按优先级建立变更

| 顺序 | 建议变更名 | 完成判定 |
| --- | --- | --- |
| 1 · P0 | `stabilize-local-oncall-smoke` | 提供可重复的本地 SOP 和测试告警。禁用来源不影响本地 Alertmanager。缺少观测源时，前端看得到明确原因，诊断与后台任务终态一致 |

| 4 · P1 | `scope-chat-and-knowledge-by-organization` | 普通对话与个人会话按企业和所有者隔离。企业共享知识、私有知识和诊断 SOP 各自按权限检索，普通聊天的 MCP 不带故障分析工具 |

| 6 · P2 | `deliver-alertmanager-notifications` | Alertmanager 将告警推送到本地工作台，重复告警合并，恢复事件更新原记录。规则启用时，授权范围内只自动建立一个任务 |

| 9 · P3 | `add-mongodb-chat-storage` | 正式部署可用 MongoDB 保存聊天。旧会话可按原 ID 迁移，消息分页、数据归属和重试均通过测试 |
