## Context

告警来源聚合在拉取时会容忍单个来源失效，但配置构建阶段会验证空地址。诊断图初始化在后台任务中执行，初始化失败可以使后台任务进入失败而诊断仍显示等待。现有诊断详情提供可扩展的结果载荷，SSE 消费端可以展示安全的中文消息。

## Goals

- 在本地复用真实 Alertmanager、Markdown SOP 和 Milvus 验证链路。
- 持久化可理解的诊断启动失败，确保重新查看任务和重放事件时也能定位原因。

## Decisions

1. 将空白字符串作为停用告警来源的约定。仍校验来源对象和已配置地址对应的连接信息。这样现有模板可以直接表示停用的可选 Prometheus 来源，启用来源继续走已有 API。
2. 在创建诊断图时读取 CLS 地域、主题，再组装模型、MCP 和检索依赖。配置缺失使用专门的内部异常，把固定中文提示存入诊断结果的可选 `failureReason` 并发出标准 `SYSTEM_UNAVAILABLE`。复用任务错误事件和已有诊断失败状态，真实 MCP 失败仍走图内报告与审计路径。
3. 工作区的报告区域从任务结果读取失败原因。通过已有的诊断详情恢复历史，错误内容来自固定提示，避免暴露配置值和底层异常。共享契约注明可选字段。
4. 本地演练复用现有显式告警发布和 SOP 导入脚本，文档说明只导入及查询测试材料的路径，以及未配置 CLS 时的预期终态。自动化测试通过测试传输避免云调用。

## Risks / Trade-offs

- 所有告警来源均停用时缺少可用数据。沿用服务不可用响应和告警列表的重试状态。
- 旧的诊断记录可能没有失败原因，页面采用已有的失败占位内容。新任务按已有 API 字段和状态返回。
