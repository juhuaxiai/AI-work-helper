## Context

本地诊断以持久任务运行，结果包含测试 Trace。验证以原诊断的已保存证据为输入，可单独审批和恢复。

## Decisions

- 服务端仅从已完成的本地 TTS 诊断提取可验证的实测阶段。生成不可变计划，保存版本、Trace、证据引用、镜像内容 ID、审批期限和执行编号。企业本部门可执行批准、拒绝和取消。
- 批准转换与验证 job 入队在同一个事务；其他状态的重复批准返回原记录。Workers 按已注册 kind 领取任务。
- 独立进程调用 Docker，由内容 ID 启动固定镜像，使用非 root、无网络、只读根文件系统、无宿主文件挂载及资源限制。TTS 对照负载在沙箱内运行。
- Docker 容器名称由执行编号派生，恢复时查询状态而不重复启动已停止的容器。若恢复时无法确认是否启动，计划以失败和原因终止。完成后先持久化证据和报告，再回收容器。

## Risks / Trade-offs

测试只覆盖预设本地负载。真实测试环境需要另行配置可验证的网络边界。审批期间和恢复时使用持久计划，避免在等待期间占用工作线程。
