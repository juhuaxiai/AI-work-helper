## Context

聊天使用现有仓库接口，鉴权从登录态解析账户和组织。SQLite 审计引用会话主键，切换存储需同步路由聊天审计。

## Goals / Non-Goals

- 保留会话、消息、摘要、引用及聊天工具审计，支持稳定的历史分页和重试。
- 诊断、账号、反馈和后台任务仍在业务库。

## Decisions

- `chatStorage.driver` 默认 `sqlite`，可显式选 `mongodb`。MongoDB 使用独立集合保存会话、消息和聊天审计。使用副本集或分片集群支持事务。消息的时间和 ID 构成排序键，游标必须属于当前会话。
- 直接读取已有 SQLite 行，按会话事务导入。独立迁移标记在重复迁移和目标删除后仍可识别已导入会话。遇到同 ID 冲突停止，暂停聊天写入后执行。数据库凭据仅从本地 JSON 读取。
- 浏览器请求固定大小的最新页并按需加载更早内容。原有无分页参数的历史读取保持兼容。向模型发送上下文继续遵循已有权限复核与记忆压缩。

## Risks / Trade-offs

- 单机 standalone 无法执行事务。启用 MongoDB 时 `/ready` 明确报告存储拓扑状态，失败沿用统一错误响应。
- SQLite 快照保留用于回退。回退需先安排切换后会话的处理。
