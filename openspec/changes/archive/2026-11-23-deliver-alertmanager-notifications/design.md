## Context

现有活动告警列表从服务端拉取。Alertmanager 通知需要独立保存，以便用户重新打开工作台时恢复告警历史。

## Decisions

- 每个 webhook 来源使用自己的服务端 token，并由组织目录分配给一个企业。源配置决定是否按具体告警名创建自动诊断。
- 使用来源、企业、指纹和归一化触发时间计算记录 ID。以一个 SQLite 事务创建首次告警、诊断和持久任务。告警解除更新原记录，并阻止迟到的触发事件回退状态。
- 本部门的工作台每三秒更新本企业通知。单条告警详情保留状态、发生时间和当前账号可打开的诊断。
- 本地 Prometheus 规则评估 TTS 示例工作负载的实测指标。工作台接收 Alertmanager 的 firing 与 resolved 事件。

## Risks / Trade-offs

浏览器提醒采用短周期拉取，数据到达告警服务后的延迟也受 Prometheus 和 Alertmanager 配置控制。工作台刷新后可以重新读取持久化记录。
